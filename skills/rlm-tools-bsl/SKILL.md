# rlm-tools-bsl

`rlm-tools-bsl` — движок навигации и анализа исходников 1С/BSL. Плагин
`1c-properties` держит его на машине проекта и отдаёт агенту как native tools:
провайдеру не нужен отдельный MCP-конфиг.

## Когда использовать

- Нужно найти модуль, процедуру, вызовы, перехваты расширений, движения
  документа, состав объекта или связи между объектами.
- Нужен ответ по исходникам конфигурации, а не по имени файла.
- Простой вопрос «прочитай один файл» решается обычным чтением файла; rlm
  нужен, когда важна связь между модулями и метаданными.

## Порядок работы

1. `rlm_start({ query })` — открыть сессию. Путь к проекту подставляется
   автоматически; для другого корня передай `path` или `project`.
   Для BSL в режиме slim выбери `domains`: `код`, `структура`, `связи`,
   `документ`, `расширения`, `поиск` или `весь каталог`.
2. `rlm_execute({ session_id, code })` — Python с хелперами rlm. Переменные
   сохраняются между вызовами; связанные операции делай одним вызовом.
3. `rlm_end({ session_id })` — закрыть сессию, когда работа закончена.

`rlm_help` — меню и справка: тема (`rlm_help({ topic: "проведение" })`),
домен (`domain: "код"`), категория, раздел или подписи хелперов. Если не
понятно, что означает поле ответа (`source`, `owner`, `partial`,
`index_coverage`), спроси `rlm_help({ section: "coverage" })`.

## Правила

- Не выдумывай имена хелперов. Если подписи нет — вызови `rlm_help` или
  добавь `domains` к следующему `rlm_execute`; подписи придут в ответе.
- `rlm_projects` и `rlm_index` меняют состояние. Для `add`, `update`,
  `remove`, `rename`, `build`, `update`, `drop` нужен пароль проекта: спроси
  его у пользователя, не подставляй догадку. `action: "info"` и
  `action: "list"` безопасны.
- Первый запуск движка занимает до минуты: плагин ставит пакет через `uv` и
  поднимает локальный сервер. Не повторяй вызов сразу, дождись ответа.
- Движок работает на машине проекта, а не на машине bb-сервера. Для
  удалённого проекта путь и индекс относятся к его машине.
