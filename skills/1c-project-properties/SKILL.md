# Параметры 1С проекта

Плагин хранит параметры подключения в файле `.bb/1c-project.json` в корне
проекта. Файл переезжает вместе с проектом; плагин читает его и старый
`.dsh/1c-project.json` (для проектов, перенесённых из DSH).

## Что читать

| Источник | Когда |
| --- | --- |
| `project_1c_params` | Нужны путь к базе, платформа, пользователь, каталог выгрузки. Пароль не возвращается. |
| `bb 1c-properties show [проект] --json` | То же из терминала; проект — имя, id или путь. |
| `bb 1c-properties list --json` | Все проекты bb и признак наличия файла параметров. |

Не угадывай путь к базе, платформе или логин: возьми их из параметров
проекта. Если поле пустое, скажи об этом пользователю, а не подставляй
значения из другого проекта.

## Операции

| Команда | Что делает |
| --- | --- |
| `bb 1c-properties check [проект]` | Проверяет путь и открывает базу внешним соединением. Для платформы 8.5 используется `V85.COMConnector`, для 8.3 — `V83.COMConnector`. |
| `bb 1c-properties dump [проект]` | `DESIGNER /DumpConfigToFiles` в каталог выгрузки. Ключи: `--dir`, `--format hierarchical|plain`, `--update`, `--clean-locks`. |
| `bb 1c-properties load [проект] --yes` | `DESIGNER /LoadConfigFromFiles` и `/UpdateDBCfg`. Без `--yes` команда отказывается. |
| `bb 1c-properties extensions [проект]` | Выгружает все расширения в `<каталог выгрузки>/Extensions`. |
| `bb 1c-properties status [проект]` | Состояние текущей операции на машине проекта. |
| `bb 1c-properties cancel [проект]` | Останавливает операцию. |
| `bb 1c-properties platform --help` | Операции с XML, CF/CFE, EPF/ERF, FILE-базами и DT, проверка синтаксиса, YAxUnit и Vanessa Automation. |
| `bb 1c-properties init [проект]` | Инициализирует BSL Flow и подключает его скиллы. |
| `bb 1c-properties skills [проект]` | Подключает или обновляет скиллы проекта. |
| `bb 1c-properties rlm <tool>` | Вызывает инструмент `rlm-tools-bsl`; аргументы — `--args` или `--args-file`. |
| `bb 1c-properties cleanup --scan` | Показывает категории временных и сборочных файлов и их размер. |
| `bb 1c-properties cleanup --categories <ids|all> --yes` | Удаляет выбранные категории. |
| `bb 1c-properties tools --check` | Показывает версии и обновления инструментов в текущем режиме. |
| `bb 1c-properties tools --update` | Устанавливает или обновляет инструменты в текущем режиме. |

Долгие команды ждут завершения; добавь `--no-wait`, чтобы только запустить, и
`--json` для машинного вывода. Одна операция на машину: пока идёт выгрузка,
вторая команда получит отказ.

Для `platform` сначала выполните `preview <операция>` в нужной рабочей
копии или укажите её через `--environment`. Для операций, меняющих базу,
подтвердите показанную цель и передайте код через `run <операция> --confirm`.
После сбоя проверьте состояние цели и при повторе передайте идентификатор
предыдущего запуска через `--inspected`. Результат доступен в `platform
journal`, `platform show <id>` и `platform artifact <id> --artifact <имя>`.
Для восстановления и тестов нужен профиль типа `test`.

## Правила

- `load` заменяет конфигурацию базы необратимо. Запускай её только по явной
  просьбе пользователя и только после того, как он подтвердил последствия.
- Перед `dump` проверь, что в форме или параметрах задан путь к платформе;
  пустое значение в проекте означает общую настройку плагина.
- `--clean-locks` снимает `.cfl` только у файловой базы. Не включай его без
  необходимости.
- Не редактируй `.bb/1c-project.json` вручную без просьбы: в файле лежит
  пароль открытым текстом, и его нельзя коммитить.

## BSL Flow, скиллы и rlm

- `bb 1c-properties init` готовит BSL Flow и копирует его скиллы в `.bb/skills`.
  Параметры базы заполняются в панели 1С. Для диагностики отдельного плагина `bb-unica` используй `bb unica status`.
- `bb 1c-properties tools --check` — версии и обновления; `--update` — установка.
  Не запускай обновление без просьбы пользователя, если он не просил
  инициализацию.
- Повторный `bb 1c-properties skills` обновляет управляемые копии. Не удаляй
  каталоги в `.bb/skills`, которых нет в `.bb/1c-skills.json`: они
  пользовательские.
- `rlm_*` — native-инструменты плагина для анализа исходников. Начни с
  `rlm_start`, работай через `rlm_execute`, закончи `rlm_end`. Подробности — в
  скилле `rlm-tools-bsl`.
- `rlm_index` меняет индекс и требует пароль проекта. Не вызывай build/update
  без явной просьбы пользователя.

## Второе мнение по изменению

Для независимого ревью открой вкладку «Второе мнение» в исходном треде.
Укажи задачу, начальный коммит диапазона или идентификатор локального
изменения OpenSpec, вопрос рецензенту, провайдера и модель. Плагин проверяет
связь треда с его рабочей копией, фиксирует текущий `HEAD` и проверяет наличие
выбранных материалов. В вопросе указывай только данные, необходимые для ревью,
без секретов и параметров доступа к базе.

BB 0.50.1 и SDK 0.6.157 предоставляют `accept-edits`, `auto` и `full`.
Отдельный worktree создаётся от выбранного `HEAD` после подтверждения.
`accept-edits` разрешает запись в созданную копию. Просьба рецензенту работать
командами чтения не заменяет `read-only`. При строгом требовании `read-only`
сообщи об ограничении и оставь запуск заблокированным. Незакоммиченные файлы
в отдельную копию не попадают.

Для CLI доступны `bb plugin rpc inspect 1c-properties reviewStart` и RPC
`reviewContext`, `reviewList`, `reviewEvidence`. Указывай исходный `threadId`
и `environmentId`. `reviewStart` требует явного `isolatedWorktree: true`.
Если ответ о запуске потерялся, сначала проверь `reviewList` у исходного треда.

Открывай результат из списка обсуждений. Уточнения отправляй в тот же тред,
чтобы сохранить историю. Для ревью по OpenSpec вкладка показывает наличие
`review.json` в исходной копии. Допуск и актуальность доказательств определяет
BSL Flow по настроенному маршруту.

## Очистка проекта

- Сначала `bb 1c-properties cleanup --scan` и покажи пользователю категории и
  размеры. Не запускай удаление «на всякий случай».
- `temp` и `agent-scratch` безопасны. `build-cache`, `artifacts`,
  `extension-sources`, `root-binaries`, `worktrees` и `root-dump` — нет:
  удаляй их только по явному решению пользователя.
- `.git`, `.bb`, `.bsl-flow`, `openspec`, `src`, `tests`, `docs` и файлы
  BSL Flow защищены; если ошибка говорит «защищённый путь», не обходи её.
