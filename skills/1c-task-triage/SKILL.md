# Разбор новых задач

1. Уточни проект и источник очереди из запроса или контекста треда. Для BB Tasks с привязанным проектом выполни `bb tasks list --status backlog,todo --limit 20 --json`. Для указанного локального каталога OpenSpec выполни `openspec list --json` в корне планирования и прочитай только артефакты выбранных изменений. Если OpenSpec CLI недоступен, прочитай артефакты явно перечисленных изменений. При ошибке привязки или отсутствии очереди укажи причину и остановись, если пользователь не назвал альтернативный источник.
2. Для каждой задачи приведи идентификатор, ожидаемый результат, недостающие входные данные и следующий шаг. В 1С проверь наличие сведений о затронутых объектах, рабочем окружении, критериях проверки и обязательности ревью. Если риск или размер нельзя оценить по фактам, зафиксируй, какие сведения нужны для решения.
3. Верни список с ссылками на исходные задачи. При отсутствии записей сообщи, какую очередь проверил. Исходники, задачи, чеклисты, BSL Flow и Automations остаются в исходном состоянии. Разбор не запускает исполнителей и не отправляет сообщения.
