# bb-plugin-1c-properties

Параметры 1С в разрезе проекта bb: путь к базе, пользователь и пароль, путь к
платформе, код доступа и каталог выгрузки. Плагин показывает их во вкладке
настроек и в панели «1С: параметры», проверяет подключение и запускает
пакетные операции Конфигуратора. Там же — инициализация BSL Flow, подключение
скиллов BSL Flow и запуск `rlm-tools-bsl` для анализа кода.

Порт плагина
[DSH-1CProjectProperties](https://github.com/Mempemp/DSH-1CProjectProperties)
для bb (MIT). Из DSH перенесено ядро: параметры проекта, автопоиск платформ и
баз, проверка подключения, выгрузка/загрузка конфигурации и выгрузка
расширений. Правила 1С не копируются: проект инициализируется установленным
BSL Flow, а `rlm-tools-bsl` подключён как native-инструменты bb. Справка по
платформе и 1С:Напарник в плагин не входят.

## Возможности

- Вкладка «1С» в потоке с рабочей папкой. Monaco открывает BSL и XML, показывает дерево файлов и метаданных, поддерживает F12, Ctrl+S, диффы и операции с индексом Git. Ссылки на выделенные строки можно добавить в композер. Подробности в [инструкции редактора](docs/editor.md).
- Список проектов bb с признаком «файл параметров есть». Параметры проекта
  лежат в `<проект>/.bb/1c-project.json` и переезжают вместе с ним.
- Старый `<проект>/.dsh/1c-project.json` читается как fallback; сохранение
  пишет `.bb/1c-project.json` и старый файл не трогает.
- Автопоиск установленных платформ 1С и баз из `ibases.v8i` (пользовательский,
  общий и внешние списки через `CommonInfoBases`).
- Проверка подключения: путь к платформе, каталог базы и `1Cv8.1CD`,
  доступность сервера по порту, затем внешнее соединение через COM. Для
  платформы 8.5 используется `V85.COMConnector`, для 8.3 — `V83.COMConnector`.
- Операции Конфигуратора: `/DumpConfigToFiles`, `/LoadConfigFromFiles` с
  `/UpdateDBCfg` (динамическое обновление), выгрузка всех расширений.
  Прогресс, время, число файлов, версия конфигурации и лог видны в карточке.
- Операции платформы из панели проекта, вкладки «1С» и CLI. Именованные
  dev/test-профили, сборка и разбор артефактов, FILE-базы и DT, синтаксис,
  YAxUnit и Vanessa Automation. Журнал привязан к рабочей копии.
  Дерево поддерживает импорт и экспорт EDT, поставку CF и обновление CFU
  с проверкой SHA-256 и резервной копией. В разделе инструментов хоста
  доступны обнаружение утилит и просмотр кластеров и сеансов через RAS.
  [Документация операций и отчётов](docs/platform-operations.md)
- Агентный инструмент `project_1c_params` и CLI `bb 1c-properties` для тех же
  данных и операций.
- Инициализация BSL Flow установленным скриптом `1c-init-project`: Git,
  `openspec/config.yaml` со схемой `bsl-flow`, `AGENTS.md`, `bsl-flow.yaml` и
  sentinel. Существующие файлы сохраняются.
- Подключение скиллов BSL Flow (`1c-*` из `~/.agents/skills`) в `<проект>/.bb/skills`. Повторный запуск обновляет управляемые копии и сохраняет пользовательские файлы.
- `rlm-tools-bsl`: плагин ставит пакет через `uv` в свой каталог на машине
  проекта, поднимает streamable HTTP MCP на loopback и отдаёт агенту
  native-инструменты `rlm_start`, `rlm_execute`, `rlm_end`, `rlm_help`,
  `rlm_projects`, `rlm_index`. Первый вызов запускает движок автоматически.

## Архитектура

- `server.ts` — фабрика плагина: настройки, RPC для UI, CLI и агентный
  инструмент. Список проектов берётся из `bb.sdk.projects`, поэтому проект
  определяется по bb-проекту, а не по рабочему каталогу процесса.
- `host.ts` — host entry. Файловые и процессные операции выполняются на машине
  проекта через `bb.hosts.experimental_client`, поэтому плагин работает и с
  удалёнными окружениями bb.
- `contract.ts` — контракт host RPC; `rpc.ts` — контракт UI RPC.
- `lib/` — разбор `.v8i`, поиск платформ, файл параметров, аргументы
  Конфигуратора, очередь заданий, проверка через COM, BSL Flow bootstrap и
  копирование skills, жизненный цикл `rlm-tools-bsl` и MCP-прокси.
- `app.tsx` — общая вкладка для Settings и панели навигации.
- `skills/rlm-tools-bsl` — скилл с порядком работы rlm; включается агенту
  только для 1С-проектов.

Одна операция Конфигуратора на машину: 1С блокирует конфигурацию базы, поэтому
параллельный запуск всё равно упал бы на блокировке. Host worker удерживается
lease-ом, пока идёт дочерний процесс; при выгрузке плагина процесс снимается.

## Установка

```powershell
bb plugin install git:https://github.com/fokusov/bb-plugin-1c-properties.git@v0.1.4
```

Для разработки из локальной копии выполните `npm ci` и `bb plugin install .`. После правок выполните `bb plugin build .` и `bb plugin reload 1c-properties`.

Проверенная версия BB на Windows — `0.50.1`, Plugin SDK — `0.6.157`. Второе мнение использует отдельный worktree с `accept-edits`. При требовании технического запрета записи кнопка и RPC блокируют запуск. Для пишущих исполнителей с отдельными окружениями используйте [видимые дочерние треды BB](docs/workflows-manual-run.md#исполнители-в-отдельных-окружениях-bb).

## CLI

```
bb 1c-properties list [--json]
bb 1c-properties show [проект] [--json]
bb 1c-properties check [проект] [--json]
bb 1c-properties dump [проект] [--dir <каталог>] [--format hierarchical|plain] [--update] [--clean-locks] [--no-wait]
bb 1c-properties load [проект] --yes [--dir <каталог>] [--no-update-db] [--no-dynamic] [--no-wait]
bb 1c-properties extensions [проект] [--dir <каталог>] [--clean-locks] [--no-wait]
bb 1c-properties status [проект] [--json]
bb 1c-properties cancel [проект] [--json]
bb 1c-properties init [проект] [--json]
bb 1c-properties skills [проект] [--json]
bb 1c-properties rlm <tool> [--args '<json>'] [--args-file <путь>] [--project <проект>] [--json]
bb 1c-properties tools [проект] [--check] [--update] [--json]
```

Проект — имя, id или путь. Без аргумента берётся проект текущего потока.
Долгие команды по умолчанию ждут завершения.

`init` устанавливает актуальный BSL Flow Core, выполняет bootstrap и копирует скиллы. `rlm` вызывает
инструмент движка напрямую, например `rlm_help` или `rlm_projects`; для
сложных аргументов удобнее `--args-file`.

## Переход на bb-unica и откат

В финальной сборке `1c-properties` правки, анализ и отладку через Unica предоставляет [отдельный плагин](https://github.com/fokusov/bb-plugin-unica/releases/tag/v0.1.0). Для работы с параметрами 1С, Конфигуратором, редактором и BSL Flow установка `bb-unica` опциональна.

Перед обновлением с переходной сборки завершите операции и остановите встроенные DAP и MCP на каждой использованной машине командами `bb 1c-properties unica debug stop <проект>` и `bb 1c-properties unica stop <проект>`. Установите финальную сборку `1c-properties`, затем `bb-unica`. Если `bb-unica` уже установлен, перезагрузите его после обновления `1c-properties`.

```powershell
bb plugin install git:https://github.com/fokusov/bb-plugin-unica.git@v0.1.0
bb unica prepare --project <ID>
bb unica status --project <ID>
bb unica policy --project <ID>
```

`bb-unica` читает текущую политику из `.bb/unica.json` и поддерживает прежний ключ `unicaPolicy` в параметрах 1С. Обновление BSL Flow сохраняет существующие навыки Unica и справочники. Подключение новых навыков и настройка тестовой отладки описаны в [документации bb-unica](https://github.com/fokusov/bb-plugin-unica/blob/v0.1.0/README.md).

Для отката остановите операции и отладку `bb-unica` на использованных окружениях, отключите плагин и верните сохранённую переходную сборку `1c-properties`. В ней выставите `unicaMode=embedded`, перезагрузите плагин и выполните `bb 1c-properties unica selftest <проект>`. Сохраните исходную сборку и параметры до обновления.

## BSL Flow и скиллы

В карточке «Готовность проекта 1С» показаны машина, каталог и отдельные состояния исходников, BSL Flow, редактора, OpenSpec CLI, Unica, ревью и тестовой ИБ. Кнопка «Подготовить BSL Flow» запускает установку Core, bootstrap и подключение скиллов. При ошибке виден этап, после которого можно повторить подготовку. Наличие маршрута ревью и параметров базы обозначается как «Не проверено» до получения соответствующего результата.

Во вкладке треда «1С → Готовность» проверки исходников и Unica используют рабочую копию треда. Кнопка «Проверить Unica» выполняет чтение исходников через отдельный `bb-unica`. Проектные файлы bootstrap переносятся в другие worktree через Git.

В карточке проекта откройте **Настройки BSL Flow**. Переключатель **Использовать BSL Flow для проекта** сохраняет `workflow.enabled` в `bsl-flow.yaml` основного каталога. Перед стартом треда BB проверяет настройку на машине этого каталога. При выключении агент получает инструкцию использовать обычный процесс проекта. Для нового изменения OpenSpec с оставшейся после bootstrap схемой `bsl-flow` инструкция указывает выбрать обычную схему явно. Существующие изменения OpenSpec и скиллы сохраняются.

Вкладка **Поля** показывает настройки по разделам, включая Council, его роли и профили моделей. На вкладке **Весь YAML** доступны новые ключи, списки и сложные значения. **Сохранить настройки** проверяет YAML и версию файла. [Карта настроек и источников](docs/bsl-flow-settings.md)

`bb 1c-properties init` проверяет BSL Flow Core, при необходимости обновляет его и запускает
`1c-init-project/scripts/Initialize-BSLFlowProject.ps1`.

BSL Flow Core ставится с актуального коммита ветки `main` в
`https://github.com/fokusov/bsl-flow`. Версия читается из `VERSION` этого
коммита. Официальный `Install-BSLFlowCore.ps1` устанавливает скиллы в
`~/.agents/skills` и схему OpenSpec `bsl-flow`. Нужны `git`, `openspec`,
PowerShell 7 и сеть. Bootstrap и статус плагина используют эту установку Core.
Команда `bsl-flow --version` показывает версию отдельно установленного CLI.

Скиллы BSL Flow копируются в `<проект>/.bb/skills`. Список управляемых копий хранится в `<проект>/.bb/1c-skills.json`. Повторный `bb 1c-properties skills` обновляет копии BSL Flow и сохраняет файлы других поставщиков.

Настройка `bb plugin config 1c-properties set bslflowSkillsRoot <путь>` меняет источник копирования. Установщик Core использует `~/.agents/skills`.

## Версии и обновления

```
bb 1c-properties tools DO3_1
bb 1c-properties tools DO3_1 --check
bb 1c-properties tools DO3_1 --update
```

`--check` читает последние версии из GitHub, `--update` ставит недостающее и
обновляет устаревшее. Те же версии и кнопки «Проверить обновления» /
«Установить или обновить» есть в карточке «Инструменты 1С» панели проекта.

Для BSL Flow сравниваются версия и коммит. Изменение `main` с тем же `VERSION` тоже требует обновления. При недоступном upstream команда инициализации сообщает о сбое проверки актуальности.

## rlm-tools-bsl

Плагин ставит `rlm-tools-bsl` через `uv` в
`<dataDir плагина>/host-data/rlm` на машине проекта (`tool`, `bin`, `python`),
поднимает сервер на `127.0.0.1:9330` (или свободном порту) и проксирует его
MCP через host entry. Агенту доступны native-инструменты `rlm_start`,
`rlm_execute`, `rlm_end`, `rlm_help`, `rlm_projects`, `rlm_index`.

- Движок стартует при первом вызове `rlm_*`; первый запуск вместе с установкой
  занимает до нескольких минут.
- Индекс не строится автоматически: `rlm_index` меняет состояние и требует
  пароль проекта. Без индекса хелперы работают через файловый обход.
- Инструменты и скилл `rlm-tools-bsl` включаются агенту только для проектов,
  которые плагин определил как 1С-проекты.
- RLM не включается автоматически и не зависит от готовности Unica. Чтобы
  добавить `rlm_*` и скилл `rlm-tools-bsl` агенту, включи «Использовать
  инструменты rlm» в карточке проекта.
- Для ручной проверки: `bb 1c-properties rlm rlm_help --project <проект>`.

## Очистка проекта

Карточка «Очистка проекта» считает размеры и предлагает категории:

| id | Что удаляется | По умолчанию |
| --- | --- | --- |
| `temp` | `tmp`, кэши Python/pytest, логи, `~$*`, миграционные логи | включено |
| `agent-scratch` | `_analysis`, `_work` | включено |
| `build-cache` | `.build`, `build` — тестовые базы, кэши Unica и rlm | выключено |
| `artifacts` | `artifacts`, `output` | выключено |
| `worktrees` | `.worktrees` — каждое рабочее дерево отдельной строкой | выключено |
| `extension-sources` | `ext_src`, `ext_kt` | выключено |
| `root-binaries` | `.cfe`, `.epf`, `.erf`, `.cf`, `.dt`, `.zip` в корне | выключено |
| `root-dump` | `Configuration.xml` и каталоги объектов в корне, только если рядом есть полноценный `src` | выключено |

Перед удалением показываются размер, число файлов и список объектов. Рискованные
категории требуют отдельного подтверждения. Удаление не выходит за папку
проекта; `.git`, `.bb`, `.bsl-flow`, `openspec`, `src`, `tests`, `docs` и
корневые файлы BSL Flow защищены. `.git` не входит в «размер проекта», чтобы
не завышать цифру.

Поверх выбранных категорий работает жёсткий набор условий — его нельзя
отключить галочкой:

- объект, изменённый меньше часа назад, не удаляется: его может держать
  запущенный инструмент или агент;
- каталог с `.git` внутри не удаляется — это репозиторий или рабочее дерево;
- рабочее дерево из `.worktrees` удаляется, только когда git не показывает
  незакоммиченных изменений, и удаляется через `git worktree remove`; ветка
  остаётся;
- если git недоступен или не может прочитать дерево, объект пропускается.

Пропущенные объекты и причина возвращаются в результате очистки и видны в CLI
и в карточке. Каждое рабочее дерево — отдельная строка, поэтому грязное дерево
не утаскивает вместе с собой чистые.

CLI:

```
bb 1c-properties cleanup [проект] --scan
bb 1c-properties cleanup [проект] --categories temp,agent-scratch --yes
bb 1c-properties cleanup [проект] --categories all --yes
bb 1c-properties tools [проект] [--check] [--update]
```

## Файл параметров

`<проект>/.bb/1c-project.json`, UTF-8, отступ 2:

```json
{
  "$schema": "bb-1c-project-properties/v1",
  "infobasePath": "C:\\Bases\\Buh",
  "user": "Администратор",
  "password": "***",
  "platformPath": "",
  "unlockCode": "",
  "dumpDir": ""
}
```

- Запись атомарная: временный файл и переименование, обрезанного JSON не будет.
- Посторонние ключи в файле сохраняются.
- **Пароль хранится открытым текстом** — не коммить файл в git.
- Пустой `platformPath` означает общее значение из настроек плагина.

## Требования

- Windows на машине проекта — для платформы 1С, COM и PowerShell.
- Платформа 1С:Предприятие 8.3 — для операций и проверки подключения.
- BSL Flow ставится плагином из GitHub: нужны `git`, PowerShell 7, `openspec` и сеть.
- `uv` на машине проекта — для установки `rlm-tools-bsl`; при первом запуске
  плагин ставит пакет сам.
- Node.js не требуется ставить отдельно: host entry исполняется bb.
