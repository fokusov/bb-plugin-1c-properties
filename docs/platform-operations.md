# Операции платформы 1С

Операции доступны в панели проекта, в разделе «Операции» вкладки «1С» и через `bb 1c-properties platform --help`. Панель проекта работает с каталогом источника проекта. Вкладка треда работает с его окружением. CLI внутри треда выбирает его окружение автоматически. Для вызова извне укажите проект и `--environment <id>` или `--thread <id>`. Относительные пути разрешаются в выбранной рабочей копии. Путь с выходом за её пределы задаётся явно как абсолютный путь на хосте.

## Профили

Именованные профили сохраняются в `.bb/1c-platform-profiles.json`. Рабочие копии на хосте источника совместно используют этот файл. На другом хосте используется файл выбранного окружения. Адрес FILE-базы можно задать относительно рабочей копии, чтобы один профиль выбирал отдельную базу для каждой копии. Базу можно выбрать из системного списка `.v8i`. Веб-базы из него исключаются.

```json
{
  "profiles": [
    {
      "name": "smoke",
      "kind": "test",
      "infobase": ".build/ib",
      "platform": "C:/Program Files/1cv8/8.5.1.1529/bin/1cv8.exe"
    }
  ]
}
```

CLI `platform save-profile <проект> --args-file <json>` принимает один объект профиля. `platform profiles` возвращает профили и адреса доступных баз. Поля `platform`, `user`, `passwordSecret` и `unlockCodeSecret` необязательны. Последние два поля содержат имена записей Env Catalog. Если Env Catalog недоступен, запуск с указанным секретом завершается до старта процесса. Встроенный профиль `project` использует существующие параметры проекта и запасной путь платформы из настроек плагина. Существующие команды `dump`, `load`, `extensions`, `status` и `cancel` сохраняют свой интерфейс.

## Запуск и подтверждение

```text
bb 1c-properties platform preview build-configuration --profile smoke --extension Example --input src/cfe --output .build/Example.cfe --json
bb 1c-properties platform run build-configuration --profile smoke --extension Example --input src/cfe --output .build/Example.cfe --confirm <код> --json
bb 1c-properties platform journal --json
bb 1c-properties platform show <id> --json
bb 1c-properties platform cancel <id> --json
bb 1c-properties platform artifact <id> --artifact operation.log
```

Предпросмотр показывает действие, рабочую копию, профиль, фактический адрес базы и исполняемый файл платформы. Для операций, способных менять базу, запуск принимает код подтверждения именно этого предпросмотра. Изменение разрешённой цели, версии файла платформы или состояния FILE-базы требует нового предпросмотра. Для восстановления DT и запуска тестов нужен именованный `test`-профиль. Для создания FILE-базы укажите новый каталог внутри существующего каталога-родителя. До записи артефакта плагин проверяет, что выходной путь свободен.

При сборке CF/CFE и разборе обратно в XML выбранная FILE-база служит промежуточной. Операция загружает конфигурацию или расширение и последовательно выгружает результат. `update-db` выполняется отдельно, для расширения укажите `--extension`. Для CFE нужно явно задать имя расширения. Для внешней обработки или отчёта вход или выход XML указывается корневым файлом. Для конфигурации или расширения указывается каталог с `Configuration.xml`.

`--no-wait` возвращает идентификатор запуска сразу. Остановка из UI либо CLI посылает запрос процессу, а итог фиксируется после его завершения. `launched` означает, что интерактивный клиент стартовал как процесс. `cancelled` и `interrupted` требуют проверить процесс и фактическое состояние изменяемой базы. После частичного сбоя запись содержит последнюю подтверждённую стадию, код платформы и доступные признаки состояния файла `1Cv8.1CD`. Для повторного изменения сначала проверь цель средствами платформы. Затем открой новый предпросмотр, подтверди действие и передай `--inspected <id>`. Созданные при сбое файлы остаются доступны для проверки.

## Проверки и BB Workflows

- `check-syntax` использует `/CheckModules` для тонкого клиента, сервера и внешнего соединения. Через `--extension` можно выбрать расширение. Отчёт `operation.log` публикуется и при ошибке синтаксиса.
- `yaxunit` запускает установленное в тестовой базе расширение YAxUnit через `RunUnitTests`. Параметр `--config` принимает JSON настроек, например фильтр по модулям. Плагин задаёт выход JUnit и завершение сеанса после тестов.
- `vanessa` принимает `--input <vanessa-automation-single.epf>` и `--config <VAParams.json>`. Плагин задаёт вывод JUnit и завершение сеанса после сценариев. Подготовка клиента тестирования и сценарии задаются в VAParams.

Подготовьте политику запуска тестовых инструментов в выделенной базе. Доступ
YAxUnit к конфигурации запуска и отчёту зависит от режима безопасности
расширения. При первом запуске Vanessa платформа может запросить разрешение
на открытие EPF и запуск внешнего компонента.

В шаге BB Workflows вызывайте CLI с явным окружением, профилем и `--json`. Команда `run` ждёт итог по умолчанию. Для изменяющих операций передавайте подтверждение, полученное для выбранной пользователем цели. Проверяйте `state`, счётчики JUnit и `artifacts`. При отсутствии отчёта, нуле выполненных тестов или наличии падений результат проверки считается ошибкой. Ревизия Git и признак локальных изменений фиксируются на момент старта. Для выбранной тестовой базы они указывают на рабочую копию вызывающего окружения. Загрузку нужной ревизии в базу задаёт сам Workflow.

## Контракт дашборда

`1c-properties.platformDashboardV1` — доступный для discovery read-only RPC. На входе `projectId` и при необходимости `environmentId` либо `threadId`. Ответ `{ version: 1, entries: [...] }` содержит до 50 последних событий в выбранной рабочей копии. В записи есть идентификатор, операция, профиль, состояние, даты, ревизия, признак локальных изменений, необходимость проверки цели и счётчики тестов. `reports` содержит ссылки вида `{ id, name }`. Передавайте их вместе с исходной областью запроса в read-only RPC `platformArtifact` или используйте в команде `platform artifact`. Отчёты и журналы до 4 МиБ доступны из вкладки «1С» для просмотра и скачивания.

### Импорт диагностики для дашборда

Сначала сохраните отчёт в выбранной рабочей копии. BSL LS должен использовать репортёр `json`, АПК — пакетный экспорт JUnit.

```powershell
bb 1c-properties platform import-diagnostics bsl-ls <projectId> --environment <environmentId> --input .bsl-flow/reports/bsl-json.json --finished-at <ISO8601> --revision <fullGitSha>
bb 1c-properties platform import-diagnostics apk <projectId> --environment <environmentId> --input .bsl-flow/reports/apk-junit.xml --finished-at <ISO8601> --revision <fullGitSha> --profile ci
```

Укажите фактическое время окончания анализа с часовым поясом. Передавайте SHA только для чистого состояния исходников, которое проверил анализатор. Если оно неизвестно или содержало незакоммиченные изменения, опустите `--revision`. Для сравнения двух запусков с одинаковыми правилами используйте одно имя профиля. При необходимости передайте `--thread` для выбора рабочей копии треда.

Импорт принимает файлы до 4 МиБ и сохраняет их на хосте BB. Проверяйте содержимое перед импортом, если отчёты могут содержать данные клиента. Для каждой рабочей копии в дашборде доступны два последних отчёта каждого инструмента. Старые артефакты остаются в данных плагина. Команда читает готовый отчёт и не запускает анализ или платформу.

`platformDashboardV2` принимает ту же область и возвращает `{ version: 2, entries, diagnostics }`. В `entries` добавлено поле `platformVersion`. Версия извлекается из записанного пути стандартной установки клиента. Для файлов вне такой структуры возвращается `null`. `diagnostics` содержит инструмент, профиль, время, заявленную ревизию, счётчики и ссылку для `platformArtifact`. Счётчики АПК показывают число проверок и число завершившихся ошибкой по JUnit. Счётчики BSL LS показывают все замечания, ошибки и предупреждения.
