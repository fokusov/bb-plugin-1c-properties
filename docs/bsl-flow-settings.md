# Настройки BSL Flow в BB

Карта основана на BSL Flow Core `0.9.0-dev.1`, коммит `bcdf44c`. Проверены шаблон проекта, движок обзора, правила пользовательского профиля и настройки, встречающиеся в рабочих проектах. Редактор сохраняет проектный `bsl-flow.yaml` на машине основного источника проекта и сохраняет произвольные ключи.

| Раздел проектного YAML | Что регулирует |
| --- | --- |
| `version` | Версия формата проектных настроек. |
| `workflow` | `enabled` — применять BSL Flow к новым задачам BB. При отсутствии ключа для настроенного проекта действует `true`. `mode`, `entrypoint` и `managed` описывают маршрут и условия готовности управляемых задач. |
| `features.self_learning_memory.enabled` | Включение Experience Ledger отдельно от журнала управляемых задач. |
| `source.paths` | Каталоги исходников, используемые при работе с проектом и проверкой привязки спецификации. |
| `environment` | `platform_bin`, `development_db`, `test_db`. Шаблон задаёт ссылки на переменные среды. |
| `test_setup` | Политика подготовки тестового окружения, каталоги YAxUnit и Vanessa, профиль рабочей станции и допустимость dev-базы как тестовой цели. |
| `verification` | Пути отчётов и доказательств, статическая проверка, unit, integration, UI и smoke. У настроенных проверок могут быть `enabled`, `provider`, `readiness` и профиль инструмента. |
| `policy` | Выбор объёма тестирования, правила Computer Use, тип тестовой базы, требования к проверкам форм и проведения, независимое ревью и лимит раундов исправления. |
| `review.enabled`, `review.routing` | Доступность ревью и маршрутизация S, M, L и высокого риска. Фиксированный маршрут движка выбирает подходящий тип проверки. |
| `review.reviewer` | `provider`, `agent`, `model`, `variant` одиночного ревьюера. Применимость зависит от выбранного маршрута и версии Core. |
| `review.council` | Включение, `max_parallel` (1–8), `allow_local_http`, `legacy_mode`, `independence`, `request_timeout_seconds` (60–900) и бюджет `currency`, `limit`, `reservation`. |
| `review.council.roles` | `brainstorm`, `intent_critic`, `architecture_critic`, `executability_critic`, `chair`. Поля роли: `enabled`, `required`, символический профиль `model` и `fallback`. |
| `llm.providers` | Именованные `protocol`, `base_url`, `token_env`. В Core есть `openai_responses`, `openai_compatible` и `anthropic_messages`. |
| `llm.models` | Именованные профили с `provider`, конкретным ID `model`, `effort` и необязательным `cost_estimate_usd`. |
| `review.permissions`, `review.input`, `review.runtime`, `review.thresholds` | Режим чтения проекта, ограничения операций ревьюера, размер входов, таймаут и размер выхода, пороги оценок, неоправданной сложности и избыточности. |
| Расширения в рабочих проектах | Встречаются `onec.providers`, `test_setup.testpilot` и `verification.autonomy`. Их читают соответствующие версии BSL Flow или адаптеры. Поля доступны в редакторе в составе исходного YAML. |

## Приоритет и границы

- BSL Flow берёт модели, провайдеры и привязки моделей ролей из `~/.bsl-flow/config.yaml` или файла из `BSL_FLOW_USER_CONFIG`. Значения проекта имеют приоритет по полям. Форма предлагает имена унаследованных профилей и позволяет сохранить переопределение в проекте. Пустое поле привязки удаляет проектное значение для наследования.
- Кнопка **Выбрать в BB** открывает подготовку профиля для конкретной роли. Пикер использует каталог основного окружения проекта, а до его создания — каталог машины. В проект сохраняются ID модели и выбранный API-провайдер Council. Каталог BB показывает доступность модели для агента, а Council проверяет доступ к ней через настроенный API при запуске ревью.
- Значения токенов и локальные переопределения адресов провайдеров разрешает Core. Форма редактирует ссылки на окружение, а файл `.bsl-flow/providers.local.yaml` обрабатывается самим Core. Доступность моделей проверяется при обычном запуске ревью.
- Отключение Council оставляет обязательное ревью L и высокого риска заблокированным. Обычное M-ревью использует отдельного ревьюера.
- `workflow.enabled` меняется в основном каталоге. BB применяет его при сборке инструкций проекта и пропускает bootstrap и синхронизацию BSL Flow, когда проект выключен. Git переносит настройку в остальные рабочие копии. Запущенные задачи завершаются через контроллер BSL Flow.
- В **Полях** можно править существующие значения. **Весь YAML** позволяет добавлять и удалять ключи, расширять списки и изменять пользовательские структуры. Сохранение проверяет структуру YAML, переключатели и ревизию файла. Специальные правила допуска провайдеров, моделей и ревью остаются в Core.
