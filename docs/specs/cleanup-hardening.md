# Изменение: границы безопасности очистки проекта

- **Дата:** 2026-11-23
- **Область:** `lib/cleanup.ts`, `contract.ts`, `rpc.ts`, `server.ts`
  (`cleanup` CLI), `app.tsx` (`CleanupCard`)
- **Источник идей:** [morajabi/poo](https://github.com/morajabi/poo) (MIT) —
  разделы Safety floor, Tiers and plans, Backups в README и `docs/mods.md`

Идеи взяты по описанию правил, код poo не копировался.

## Что было

Очистка удаляла объекты категории без единой дополнительной проверки, кроме
защищённых имён и выхода за пределы проекта. Практические следы:

- `.worktrees` удалялся целиком одним объектом, поэтому рабочее дерево с
  незакоммиченными изменениями уезжало вместе с чистыми;
- каталог `build`, внутри которого оказался `.git`, удалялся как «сборочный
  кэш»;
- файл, который пишется прямо сейчас, мог попасть в «безопасную» категорию;
- `cleanupCategory.truncated` всегда был `false` — мёртвое поле.

## Что взято

1. **Жёсткие условия удаления** (poo: *safety floor*, их не отключает ни
   правило, ни настройка):
   - объект, изменённый меньше часа назад, не удаляется (poo: `hot`, «touched in
     the last hour»);
   - каталог с `.git` внутри не удаляется (poo: «project artifacts must not
     contain a `.git` entry»);
   - рабочее дерево удаляется только при чистом `git status` (poo: «worktrees
     with uncommitted work» относятся к `review` и никогда не попадают в план);
   - если git не может ответить, объект пропускается (poo: «stays on the safe
     side whenever it cannot tell»).
2. **Удаление рабочего дерева через `git worktree remove`** (poo: worktrees
   снимаются этой командой, ветка остаётся). На Windows команда запускается с
   `--git-dir` основного репозитория: с `git -C <worktree>` git не может удалить
   каталог, который сам же сделал текущим.
3. **Гранулярность по объектам внутри `.worktrees`** (poo: каждый worktree —
   отдельный item): одно грязное дерево больше не блокирует чистые.
4. **Причина пропуска в результате** (poo: `poo history` фиксирует skip и
   причину): `cleanupRun` вернул `skipped: [{path, reason}]`, это печатает CLI
   и показывает карточка.

Не взято сознательно: корзина/карантин, бэкап мелких файлов и stash перед
удалением, инкрементальный индекс сканирования, правила в TOML, планировщик,
теги/тиры сверх существующего `safe`. Для проекта bb-плагина это лишний вес;
отказ от бэкапа компенсирован тем, что грязное дерево просто не удаляется.

## Поведение

`CleanupItem` теперь несёт `lastModified` и `hot`; `CleanupCategory` больше не
несёт мёртвый `truncated` (общий флаг `CleanupScan.truncated` остался и
по-прежнему означает срабатывание лимита в 300 000 файлов).

«Горячим» объект считается по самому свежему файлу внутри: один правленный файл
делает горячим весь каталог. Это осознанно консервативная трактовка
(«что-то в этом каталоге ещё пишется»).

## Проверка

Синтетическое дерево, временный bb-проект, `bb 1c-properties cleanup
cleanup-test --categories all --yes`:

| Объект | Ожидание | Результат |
| --- | --- | --- |
| `tmp/`, `_work/`, `.build/`, `ext_src/`, `old.zip` | удалить | удалены |
| `_analysis/` (файл изменён сейчас) | пропустить как горячий | пропущен |
| `build/` с `.git` внутри | пропустить | пропущен |
| `.worktrees/clean-wt` (чистое) | удалить через git | удалено, ветка `wt-clean` осталась |
| `.worktrees/dirty-wt` (untracked файл) | пропустить | пропущен |
| `.worktrees/plain` (без `.git`) | удалить | удалено |
| `src/Configuration.xml` | не трогать | на месте |

`git worktree list` после очистки не содержит `clean-wt` и по-прежнему
содержит `dirty-wt` — метаданные репозитория согласованы.

`npx tsc --noEmit`, `bb plugin build`, `bb plugin reload 1c-properties` — чисто.

## Ограничения

- Защита «свежести» — по `mtime`. Инструмент, который пишет файл, но не меняет
  mtime (редко), её обойдёт.
- Каталоги верхнего уровня сканируются целиком, без инкрементального индекса:
  на проекте в сотни тысяч файлов скан стоит времени.
- Проверка git появилась только для `.worktrees`. Для остальных категорий
  достаточно условия про `.git` внутри.
